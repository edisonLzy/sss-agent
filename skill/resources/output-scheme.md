# Workflow 返回值规范（修订草案）

2026-10-27：起草成功统一使用 `command=null`、`nextScheduleAt=null`，结束本轮，后续办理交工程侧；明确的合同前置业务校验失败使用 `end`。本文件约定本次起草发起任务的模型输出；起草后结果跟进与签约通知不在本期范围。

本文件定义 `Return({...})` 中的模型统一输出规范。`SKILL.md`、首招解约子流程与委托解约子流程必须严格遵守本契约。

模型最终返回必须为合法的 JSON 对象，固定包含 **`command`**、**`nextScheduleAt`**、**`finalAnswer`**、**`reason`** 四个顶层字段。网关及下游统一采用此契约。

---

## 字段定义与契约规范

| 字段 | 类型 | 必填 | 含义与取值规则 |
| :--- | :--- | :---: | :--- |
| **`command`** | string 或 null | **是** | 流程控制指令，仅允许为 `"schedule"`、`"end"`、`"transfer_to_human"` 或 `null`。<br>- `"schedule"`：请求外部调度器在 `nextScheduleAt` 再次唤醒本流程。<br>- `"transfer_to_human"`：异常或业务需要转由人工管家接管。<br>- `"end"`：结束本条自动推进流程；不表示协议已签署或解约成功。<br>- `null`：本轮交互正常结束，可静默；不会据此关闭整条自动推进流程。 |
| **`nextScheduleAt`** | string 或 null | **是** | 请求下次唤醒调度的绝对时间戳（ISO 8601 带时区格式，如 `2026-10-26T15:00:00+08:00`）。<br>- 仅当 `command="schedule"` 时必填且必须为有效未来时间；<br>- 其他情况固定为 `null`。 |
| **`finalAnswer`** | string 或 null | **是** | **专职发向企微业主服务群的消息文本**。<br>- 当需要向群内通知起草办理进展时填写具体文本；<br>- 若本轮仅为静默巡检、内部定时挂起或静默关单、无需打扰群聊时，必须填 `null`。 |
| **`reason`** | string | **是** | 本轮决策原因、终止说明、调度目的或异常说明（非空字符串）。作为全链路追踪、日志排查、BI 审计与回放的核心说明字段。 |

---

## 核心设计与使用原则

### 1. 业务事实与流程结束
* 起草、授权等业务事实通过工具及工程侧持久化，模型输出本身不能证明合同操作成功。
* 入口沿用 `query_owner_termination_agreement` 及原参数做协议防重；本期不在 `triggerAutoTermination` 返回后再次查询合同结果。
* 起草成功或申请执行中输出 `command=null`、`nextScheduleAt=null`；需要且允许群发时，只播报已确认的办理进展。后续办理交工程侧，不安排催签。
* 明确业务阻断或合同返回申请失败/人工终止时输出 `end`，只结束本次发起任务。技术异常或未知结果转人工，不盲目重试。
* `command=null` 不关闭推进单，也不会自动创建后续调度。

### 2. 私聊与群聊出口职责分离
* **私聊资管 / 租务管家**：在推理循环中作为独立的 Agent 业务工具直接调用发送。
* **群聊出口唯一化**：`finalAnswer` 专门作为企微业主群消息的唯一下发通道。
  * 需要群发办理进展时：填入正文，网关统一做风控、幂等并下发群聊；
  * 无需群发时：填入 `null`，下游静默处理，严禁发送空消息。

### 3. 异常容错与转人工（`transfer_to_human`）
* 合同触发明确返回业务阻断或 `applyStatus=3/4` 时，按 [起草返回处理](tool-contracts.md#起草返回处理) 输出 `end`，记录实际返回信息；本期不追加失败详情查询。
* 当业务规则要求转人工，或依赖的写工具调用发生技术异常、超时且无法自动恢复时：
  * `command` 设为 `"transfer_to_human"`；
  * `finalAnswer` 填入向业主群发送的安抚话术（如 *“抱歉系统遇到问题，已为您转接人工管家处理...”*）；
  * `reason` 填入明确的接口报错或转人工原因（供工单系统和人工管家排查）。

## 返回示例（JSON Schema Examples）

### 示例 1：静默关单并终止任务（如：交割发现物损 / 资管线下自跟进）
假设业务规则已明确物损需要终止自动推进；服务端校验事实后记录提前结束，不关闭原协同单：
```json
{
  "command": "end",
  "nextScheduleAt": null,
  "finalAnswer": null,
  "reason": "上任租客退租交割存在物品损坏待赔偿，按已确认规则提前结束本次自动推进"
}
```

### 示例 2：起草成功，本轮结束
假设当前群通知场景允许播报进展，触发响应为有效 `autoApplyId`、`applyStatus=1` 且 `terminationContractId` 非空；此时尚未确认发送业主完成：
```json
{
  "command": null,
  "nextScheduleAt": null,
  "finalAnswer": "@业主 您好，您的解约协议已起草，目前正在办理后续流程，请您耐心等待。可签署时会再通知您。",
  "reason": "起草成功，本轮结束，后续办理交工程侧"
}
```

### 示例 3：起草前的定时调度挂起（如：资管追问 2h/4h/t+1、租务交割复查）
起草前需要等待特定时间后再次唤醒巡检时使用；起草成功后不使用此分支：
```json
{
  "command": "schedule",
  "nextScheduleAt": "2026-10-26T18:00:00+08:00",
  "finalAnswer": null,
  "reason": "已向资管发起解约授权确认，资管暂未回复，挂起 2 小时后进行第 1 次追问催办"
}
```

### 示例 4：业务异常触发转人工（如：接口调用失败兜底）
调用起草接口发生无法确认结果的技术异常，停止重复起草并转人工核验：
```json
{
  "command": "transfer_to_human",
  "nextScheduleAt": null,
  "finalAnswer": "@业主 您好，系统办理过程中出现微小异常，已为您转接人工服务管家跟进处理，请稍候。",
  "reason": "调用合同起草工具接口失败（微服务超时），自动转人工兜底"
}
```

### 示例 4a：明确前置业务校验不通过，结束本次发起

合同侧明确抛出业务异常“待账单支付成功后再发起解约”时，记录实际返回原因，不追加查询：

```json
{
  "command": "end",
  "nextScheduleAt": null,
  "finalAnswer": null,
  "reason": "合同起草前置业务校验不通过：待账单支付成功后再发起解约"
}
```

若原生响应只返回 `applyStatus=3` 及申请 ID、节点，则记录这些实际信息，不能套用本示例中的原因。

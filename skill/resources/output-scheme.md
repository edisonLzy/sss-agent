# Workflow 返回值规范（修订草案）

2026-10-27：起草成功统一使用 `command=null`、`nextScheduleAt=null`，结束本轮并等待工程侧合同事件；明确的合同前置业务校验失败使用 `end`。本文件约定模型输出，实际合同事件与 Agent 适配以工程接入为准。

本文件定义 `Return({...})` 中的模型统一输出规范。`SKILL.md`、首招解约子流程与委托解约子流程必须严格遵守本契约。

模型最终返回必须为合法的 JSON 对象，固定包含 **`command`**、**`nextScheduleAt`**、**`finalAnswer`**、**`reason`** 四个顶层字段。网关及下游统一采用此契约。

---

## 字段定义与契约规范

| 字段 | 类型 | 必填 | 含义与取值规则 |
| :--- | :--- | :---: | :--- |
| **`command`** | string 或 null | **是** | 流程控制指令，仅允许为 `"schedule"`、`"end"`、`"transfer_to_human"` 或 `null`。<br>- `"schedule"`：请求外部调度器在 `nextScheduleAt` 再次唤醒本流程。<br>- `"transfer_to_human"`：异常或业务需要转由人工管家接管。<br>- `"end"`：结束本条自动推进流程；合同发送业主签约事件触发的最终通知使用该指令并携带 finalAnswer，发送成功回执后完成推进。<br>- `null`：本轮交互正常结束，可静默；不会据此关闭整条自动推进流程。 |
| **`nextScheduleAt`** | string 或 null | **是** | 请求下次唤醒调度的绝对时间戳（ISO 8601 带时区格式，如 `2026-10-26T15:00:00+08:00`）。<br>- 仅当 `command="schedule"` 时必填且必须为有效未来时间；<br>- 其他情况固定为 `null`。 |
| **`finalAnswer`** | string 或 null | **是** | **专职发向企微业主服务群的消息文本**。<br>- 当需要向群内通知协议进展、催签或发送办结祝福时填写具体文本；<br>- 若本轮仅为静默巡检、内部定时挂起或静默关单、无需打扰群聊时，必须填 `null`。 |
| **`reason`** | string | **是** | 本轮决策原因、终止说明、调度目的或异常说明（非空字符串）。作为全链路追踪、日志排查、BI 审计与回放的核心说明字段。 |

---

## 核心设计与使用原则

### 1. 业务事实与流程结束
* 起草、授权等业务事实通过工具及业务事件持久化。模型输出本身不能证明合同操作成功。
* 起草工具明确成功后输出 `command=null`、`nextScheduleAt=null`；需要且允许群发时，`finalAnswer` 仅说明协议已起草、后续办理中。此时不创建 t+2/t+3 催签调度。
* 工程侧保存申请关联和阶段，后续合同事件按当前进度接续，不能重新进入首次起草防重入口或重复起草。具体规则见 [SKILL.md 合同事件接续规则](../SKILL.md#合同事件接续规则)。
* 合同侧“发送业主签约”事件到达服务端后，以可信 OWNER_NOTIFY 用途调用 Agent。Agent 输出 `command="end"`、最终群文案和原因；nextScheduleAt 为 null。
* 服务端持久化发送任务，收到群消息发送成功回执后，才完成自动推进、同步对应子单并取消调度。发送失败或结果未知时保留恢复状态，不能先关单再发消息。
* 自动推进完成不代表业主已签署合同；合同签署状态继续以合同侧为准。
* 前置条件明确不满足时仍可使用 end 提前结束，reason 记录原因；它与最终通知成功后的完成状态分开处理。
* `command=null` 且 finalAnswer=null 表示本轮静默结束，不能代替 end，也不会自动创建后续调度。

### 2. 私聊与群聊出口职责分离
* **私聊资管 / 租务管家**：在推理循环中作为独立的 Agent 业务工具直接调用发送。
* **群聊出口唯一化**：`finalAnswer` 专门作为企微业主群消息的唯一下发通道。
  * 需要群发提醒或祝福时：填入正文，网关统一做风控、幂等并下发群聊；
  * 无需群发时：填入 `null`，下游静默处理，严禁发送空消息。

### 3. 异常容错与转人工（`transfer_to_human`）
* 合同触发响应 `applyStatus=3` 时，先按该次 `autoApplyId` 查询详情。查询确认尚未生成协议、在准备/起草节点因 `reasonCode=1/2` 前置校验失败时，输出 `end`、`finalAnswer=null`，`reason` 保留查询返回原因；不固定依赖网关错误码 `1007`。其他申请状态及失败分类见 [自动申请结果处理](tool-contracts.md#自动申请结果处理)。
* 当业务规则要求转人工，或依赖的写工具调用发生技术异常、超时且无法自动恢复时：
  * `command` 设为 `"transfer_to_human"`；
  * `finalAnswer` 填入向业主群发送的安抚话术（如 *“抱歉系统遇到问题，已为您转接人工管家处理...”*）；
  * `reason` 填入明确的接口报错或转人工原因（供工单系统和人工管家排查）。

## 返回示例（JSON Schema Examples）

### 示例 1：静默关单并终止任务（如：交割发现物损 / 资管线下自跟进）
假设业务规则已明确物损需要终止自动推进；服务端校验事实后记录提前结束，不关闭原协同单：
```json
{
  "command": "end",
  "nextScheduleAt": null,
  "finalAnswer": null,
  "reason": "上任租客退租交割存在物品损坏待赔偿，按已确认规则提前结束本次自动推进"
}
```

### 示例 2：起草成功，本轮结束并等待合同事件
假设当前群通知场景允许播报进展，触发响应为有效 `autoApplyId`、`applyStatus=1` 且 `terminationContractId` 非空；此时尚未确认发送业主完成：
```json
{
  "command": null,
  "nextScheduleAt": null,
  "finalAnswer": "@业主 您好，您的解约协议已起草，目前正在办理后续流程，请您耐心等待。可签署时会再通知您。",
  "reason": "起草成功，本轮结束，等待工程侧投递合同后续事件"
}
```

### 示例 3：起草前的定时调度挂起（如：资管追问 2h/4h/t+1、租务交割复查）
起草前需要等待特定时间后再次唤醒巡检时使用；起草成功等待合同事件不使用此分支：
```json
{
  "command": "schedule",
  "nextScheduleAt": "2026-10-26T18:00:00+08:00",
  "finalAnswer": null,
  "reason": "已向资管发起解约授权确认，资管暂未回复，挂起 2 小时后进行第 1 次追问催办"
}
```

### 示例 4：业务异常触发转人工（如：接口调用失败兜底）
调用起草接口发生无法确认结果的技术异常，停止重复起草并转人工核验：
```json
{
  "command": "transfer_to_human",
  "nextScheduleAt": null,
  "finalAnswer": "@业主 您好，系统办理过程中出现微小异常，已为您转接人工服务管家跟进处理，请稍候。",
  "reason": "调用合同起草工具接口失败（微服务超时），自动转人工兜底"
}
```

### 示例 4a：合同前置业务校验不通过，结束本次推进

触发响应 `applyStatus=3` 后查询同一 `autoApplyId`，查询确认 `terminationContractId=null`、`currentNode=1`、`reasonCode=2`，且 `reason` 为“待账单支付成功后再发起解约”时：

```json
{
  "command": "end",
  "nextScheduleAt": null,
  "finalAnswer": null,
  "reason": "合同起草前置业务校验不通过：待账单支付成功后再发起解约"
}
```

### 示例 5：收到合同发送业主签约事件，最终通知并结束自动推进

仅在服务端已确认合同发送签约事件、运行用途为 OWNER_NOTIFY 时使用：

```json
{
  "command": "end",
  "nextScheduleAt": null,
  "finalAnswer": "@业主 您好，您的解约协议已发送，请留意查收并完成签署。",
  "reason": "已收到合同发送业主签约事件，发送本次客户通知后结束自动推进"
}
```

### 示例 6：解约交割完成，业主签约办结祝福并调研不合作原因
```json
{
  "command": "end",
  "nextScheduleAt": null,
  "finalAnswer": "@业主 您好，您的房屋解约协议已确认签署完成，感谢您一直以来对我们的信任与支持，祝您生活愉快！请问本次不再续约的主要原因是什么呢？您的宝贵反馈将帮助我们不断提升服务质量。",
  "reason": "业主已完成解约协议签署，发送服务合作致谢祝福及不合作原因回访，流程完结自动关单"
}
```

这里 reason 是发送意图及结束原因；实际是否发送成功，以消息回执为准。
